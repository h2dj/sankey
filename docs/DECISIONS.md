# 결정 기록

개발 계획 §2.2 잠정값의 확정·변경과 구현 중 내린 결정을 날짜순으로 남긴다.

## 2026-11-02 · S1 시제품

### D1. 최대 입력 행 수: 500행 유지 (T1.6)

측정 환경: 클라우드 개발 컨테이너, Node 22, 헤드리스 Chromium. 일반 사무용 PC보다 느릴 수 있으므로 여유를 두고 판단했다.

**계산(검증 → 그래프 → 레이아웃), `npm run perf`**

| 행 | 노드 | 링크 | 중앙값(ms) | 최대(ms) |
|---:|---:|---:|---:|---:|
| 50 | 35 | 45 | 1.9 | 2.8 |
| 200 | 72 | 180 | 4.4 | 5.1 |
| 500 | 115 | 441 | 8.7 | 10.8 |
| 1000 | 160 | 472 | 8.8 | 9.3 |
| 2000 | 219 | 483 | 10.0 | 22.0 |

(1000행 이상은 무작위 연결이 겹쳐 합산되므로 링크 수가 늘지 않는다.)

**브라우저(표 + SVG 다시 그리기)**

| 행 | 붙여넣기 → 표 표시 | 키 입력 → 화면 반영 | 입력 → 차트 갱신(디바운스 150ms 포함) |
|---:|---:|---:|---:|
| 200 | 92ms | 15ms | 202ms |
| 500 | 194ms | 21ms | 206ms |

**결정**: 500행 하드 제한과 200행 초과 안내를 그대로 둔다. 500행에서도 입력 지연이 체감되지 않는다(키 입력 반응 약 20ms). 제한을 올릴지는 S5 사용자 검토에서 실제 데이터 규모를 보고 다시 판단한다. 큰 표에서 레이블이 겹치는 가독성 문제가 성능보다 먼저 한계가 될 가능성이 높다.

### D2. 완전히 빈 행은 검증하지 않는다

새 행을 추가한 직후 "필수 항목 누락" 오류가 쏟아지지 않도록, 모든 셀이 빈 행은 입력 중인 자리로 보고 건너뛴다. 셀 하나라도 채우면 검증한다.

### D3. 오류 행만 빼고 나머지는 그린다

행 단위 오류(필수 누락·숫자 오류)가 있어도 다이어그램 전체를 막지 않고 그 행만 제외한다. 그리기 자체를 막는 경우는 순환 연결과 유효 행 0개뿐이다.

### D4. 노드 색상 그룹 배정 규칙

행의 "색상 그룹"을 노드에 붙일 때, 그 노드로 **들어오는** 첫 행의 그룹을 쓰고, 들어오는 행이 없는 시작 노드는 **나가는** 첫 행의 그룹을 쓴다. (예: `석탄 → 발전 [에너지원]`이면 석탄·발전 모두 에너지원, `발전 → 가정 [소비]`이면 가정은 소비.) S2 색상 설정에서 사용자 검토 후 바꿀 수 있다.

### D5. 실행 취소 단위

같은 셀을 1.5초 안에 연달아 입력하면 한 번의 실행 취소로 묶는다. 행 추가·삭제·붙여넣기·예시 불러오기는 각각 한 단계다. 예시 불러오기도 실행 취소로 되돌릴 수 있으므로 확인 대화상자는 두지 않았다. 기록은 최대 100단계.

### D6. 표 키보드 조작

Enter/Shift+Enter·↑/↓로 같은 열의 아래/위 행으로 이동하고, 마지막 행에서 Enter를 누르면 새 행을 만든다. Ctrl(⌘)+Enter는 현재 행 아래에 새 행, Ctrl(⌘)+Delete는 현재 행 삭제. 입력란의 기본 실행 취소 대신 문서 기록(Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y)을 쓴다.

### S1 알려진 문제 처리 현황

- ~~노드 색이 편집 중 바뀐다~~ → S2 D9에서 해결.

## 2026-11-02 · S2 편집

### D7. 레이블 위치 기본값을 "안쪽"으로

계획 §2.2에는 기본값이 `outside`로 적혀 있었지만, S1에서 실제로 구현한 동작은 d3 예제와 같은 "안쪽"(왼쪽 절반 노드는 오른쪽에, 오른쪽 절반 노드는 왼쪽에 레이블) 방식이었다. 값과 동작을 맞추려고 기본값을 `inside`로 바꾸고 다음 두 가지를 제공한다.

- **안쪽**: 레이블이 차트 가운데 쪽으로 들어간다. 여백이 필요 없어 차트가 가장 넓게 그려진다.
- **바깥쪽**: 첫 열 레이블은 차트 왼쪽 밖, 마지막 열은 오른쪽 밖에 둔다. 레이블 폭을 어림해(한글 1em, 라틴 0.6em) 그만큼 여백을 잡고 다시 배치한다. 여백은 한쪽당 차트 폭의 35%를 넘지 않는다.

### D8. 팔레트 4종, 모두 흰 배경 대비 3:1 이상

기본(Okabe–Ito 색각 이상 고려 팔레트를 어둡게 조정), 차분한, 흙빛, 푸른 계열. 노드 막대는 그래픽 요소이므로 WCAG 1.4.11(비텍스트 대비 3:1)을 기준으로 했고 단위 테스트로 확인한다.

계획 T2.2의 "레이블 글자색 4.5:1 자동 선택"은, 이 앱의 레이블이 노드 색 위가 아니라 **흰 테두리를 두른 어두운 글자로 흰 배경 위**에 그려지므로(대비 약 16:1) 항상 충족된다. 팔레트의 중간 톤 색(예: `#C26A00`) 위에는 흰 글자도 검은 글자도 4.5:1이 나오지 않으므로, 색 위에 글자를 얹는 디자인은 쓰지 않는다. `readableTextColor()`는 향후 PNG 배경색 선택(S3) 등에 쓰려고 남겨 둔다.

### D9. 노드 색은 표 입력 순서로 배정

색 배정 순서를 "현재 그려진 노드 순서"에서 "표에 입력된 순서(오류 행 포함)"로 바꿨다. 앞 행이 잠시 오류가 나도 다른 노드의 색이 밀리지 않는다. 행을 삭제하면 뒤 노드의 색이 바뀔 수 있는데, 이것은 실행 취소로 되돌릴 수 있고 직접 지정한 색은 유지된다.

### D10. 차트 ↔ 표 연결 방식

- 흐름을 누르면(또는 Enter) 그 흐름을 만든 행들을 강조하고 첫 행의 **값** 셀로 초점을 옮긴다. 노드를 누르면 노드에 닿는 모든 행을 강조하고 첫 행의 **출발 노드** 셀로 옮긴다.
- 표의 셀에 초점이 가면 그 행의 흐름을 강조하고 나머지는 흐리게 한다. 표 밖으로 초점이 나가거나 Esc를 누르면 해제된다.
- 차트 안 키보드 이동은 **roving tabindex**: Tab 한 번으로 차트에 들어가 방향키·Home·End로 노드(왼쪽 열부터) → 흐름 순으로 이동한다. 흐름이 수백 개여도 Tab 횟수가 늘지 않는다.
- 미리보기 SVG는 상호작용이 있으므로 `role="group"`(설명 `aria-roledescription="생키 다이어그램"`)으로 두고, 내보내기용 정적 SVG는 `role="img"`로 그린다. 정적 SVG에만 `<title>` 툴팁을 넣는다(미리보기는 직접 만든 툴팁과 겹치지 않도록).

### D11. 차트는 미리보기 폭에 맞춰 그린다

처음에는 960px 기준으로 그린 뒤 화면 폭에 맞춰 줄였는데, 3단 배치에서 미리보기가 약 700px이 되면 13px 레이블이 9.5px로 보였다. 미리보기 폭을 ResizeObserver로 재서(20px 단위로 반올림) 그 폭으로 그리므로 "글자 크기" 설정이 화면 크기와 일치한다. 560px보다 좁으면 560px로 그려 줄여 보인다(레이블 겹침 방지).

### D12. 배치

1400px 이상은 데이터 | 미리보기 | 설정 3단, 960~1399px은 데이터 | 미리보기 2단에 설정을 미리보기 아래에 둔다. 설정은 섹션마다 접을 수 있다(`<details>`). 960px 미만 탭 전환은 T4.2.

## 2026-11-02 · S3 파일 입출력

### D13. 글꼴: Pretendard 분할 파일 자체 호스팅

- `npm run fonts`(dev·build 전에 자동 실행)가 Pretendard 1.3.9(OFL-1.1)의 유니코드 범위별 분할 woff2(일반 400·굵게 600, 각 92개)를 `public/fonts/`로 복사한다. 분할별 범위 목록 `src/fonts/manifest.ts`만 저장소에 넣는다.
- 앱은 시작할 때 FontFace API로 등록만 하고, 브라우저는 화면에 실제로 쓰인 글자가 든 분할만 내려받는다. 외부 CDN을 쓰지 않으므로 "외부 요청 0건" 검사를 유지한다.
- **PNG**: SVG를 `<img>`로 그려 캔버스에 옮기는 방식이라 외부 글꼴을 불러올 수 없다. 그래서 문서에 쓰인 글자가 든 분할만 data URI로 SVG에 넣는다(예시 예산 차트 기준 일반 7~9개 + 굵게 몇 개). 컨테이너의 기본 한글 글꼴(WenQuanYi)과 모양이 달라 적용 여부를 눈으로 확인했다.
- **SVG**: 기본은 글꼴을 넣지 않는다(편집 프로그램에서 시스템 글꼴로 고치기 쉽고 파일이 작다). "글꼴 포함"을 고르면 PNG와 같은 방식으로 넣는다. 윤곽선 변환은 후속.

### D14. CSV 인코딩

- 읽기: BOM(UTF-8, UTF-16 LE/BE)을 먼저 보고, 없으면 UTF-8로 엄격하게 읽어 실패하면 EUC-KR(브라우저의 `euc-kr`은 CP949를 포함)로 다시 읽는다. 엑셀 "유니코드 텍스트"(UTF-16 탭 구분)도 읽는다.
- `.xlsx`(ZIP 머리)는 따로 알아보고 "CSV UTF-8로 저장" 방법을 안내한다. NUL·깨진 문자가 많으면 텍스트가 아니라고 안내한다.
- 쓰기: UTF-8 + BOM, CRLF. 엑셀에서 열어도 한글이 깨지지 않는다.

### D15. 단위는 값 열 이름으로 왕복

CSV에는 제목·색 설정을 넣지 않는다(표 데이터만). 단위는 값 열 이름에 `값 (백만 원)`처럼 붙여 내보내고, 가져올 때 읽는다. "새 데이터로 바꾸기"면 단위도 바꾸고, "뒤에 추가하기"면 지금 단위가 비어 있을 때만 채운다.

### D16. 수식 주입 방지

`=`, `+`, `-`, `@`로 시작하면서 숫자 모양이 아닌 칸은 내보낼 때 앞에 `'`를 붙여 엑셀이 수식으로 실행하지 않게 한다. 가져올 때는 같은 규칙으로 떼어 내 원래 값을 되살린다(`-5` 같은 숫자는 그대로).

### D17. 가져오기 흐름

파일 선택·끌어다 놓기(대화상자 안 또는 데이터 영역 전체) → 인코딩·구분자·줄 수 요약 → "첫 줄은 열 이름" 확인 → 열 맞추기(별칭으로 자동 추정: 출발/출발지/source/from …) → 미리보기 5행과 "가져온 뒤 고칠 오류 N건" → 바꾸기/추가. 실패하면 원인을 보이고 표는 건드리지 않는다. 가져오기는 실행 취소 한 번으로 되돌린다. 예시 CSV를 내려받을 수 있다.

### D18. 내보내기 SVG는 core에서 문자열로 만든다

화면의 SVG를 복제하지 않고 `renderSvgDocument()`가 차트 모델로 새로 만든다. 화면의 강조·확대 상태나 상호작용 속성이 섞이지 않고, Node 단위 테스트로 검증할 수 있다. 그리기 규칙이 React 컴포넌트와 두 곳에 있으므로, 시각 요소를 바꿀 때는 둘 다 고쳐야 한다(`svgDocument.test.ts`, `settings.spec.ts`가 일부를 지킨다).

### D19. 내보내기 기본값

차트 폭은 "지금 미리보기와 같게"(화면에서 본 그대로), PNG는 2배·흰 배경, 제목·설명·단위 포함. 파일 이름 기본값은 제목이고 금지 문자를 지운 이름을 미리 보여 준다. 같은 세션에서 다시 열면 지난 선택(파일 이름 제외)을 유지한다.

### 확인이 더 필요한 것

- 헤드리스 Chromium은 한글 다운로드 파일명을 `download`로 바꾼다(E2E는 영문 이름으로 확인). 실제 브라우저(Chrome·Edge·Safari·Firefox)에서 한글 파일명이 유지되는지 출시 전 점검에서 확인한다.
- Safari에서 data URI 글꼴이 든 SVG를 캔버스에 그릴 때의 동작은 WebKit E2E·실기기에서 확인한다(계획 §6 위험).

## 2026-11-02 · S4 저장·반응형·접근성·배포

### D20. 브라우저 임시 저장(F-07)

- 변경 후 1초 뒤 `localStorage`의 `sankey-maker:autosave`에 저장한다. 탭을 숨기거나 닫을 때(`visibilitychange`·`pagehide`)는 기다리지 않고 바로 저장한다. 실행 취소 기록은 저장하지 않는다.
- 다시 열면 저장된 작업으로 시작하고 상단에 "지난 작업을 불러왔습니다(시각)"를 보인다. 저장된 것이 없으면 예산 예시로 시작한다.
- 저장값은 불러올 때 구조를 검사한다. 손상됐거나 더 새 버전에서 저장한 내용이면 지우지 않고 예시로 시작하며 알린다(편집하면 그때 덮어쓴다). 빠진 설정은 기본값으로, 타입이 틀린 값·잘못된 색은 버린다. 형식이 바뀌면 `persist.ts`의 `migrate()`에 단계별 변환을 더한다.
- 저장 공간 부족과 저장소 차단(사생활 보호 모드 등)을 구분해 "CSV로 내려받아 보관하세요"를 안내한다.
- 상단의 "저장 안내"에 저장 위치·한계(기기·브라우저 한정, 사이트 데이터 삭제 시 사라짐, 여러 탭 동시 편집 시 마지막 저장이 남음)를 적었다(기획서 §11, §16 위험 대응, 수용 기준 A8).
- **알려진 한계**: 같은 브라우저의 두 탭에서 동시에 고치면 마지막에 저장한 탭이 이긴다. 탭 간 동기화는 하지 않는다.

### D21. 새로 만들기

확인 창("지우고 새로 시작" / "먼저 CSV로 보관하기" / 취소)을 거친다. 빈 문서로 바꾸는 것도 실행 취소 한 단계라 바로 뒤에는 되돌릴 수 있지만, 새로고침 뒤에는 되돌릴 수 없음을 창에 적었다.

### D22. 좁은 화면(960px 미만)

- 데이터·미리보기·설정을 WAI-ARIA 탭(방향키·Home·End 이동)으로 나눈다. 데이터 탭에는 오류 수 배지를 붙여 다른 탭에서도 오류가 있음을 알 수 있게 했다.
- 차트는 최소 560px로 그리고 **줄이지 않고** 상자 안에서 가로로 스크롤한다(S2까지는 축소해서 글자가 약 7px로 보였다). 페이지 자체에는 가로 스크롤이 없다.
- 차트의 흐름을 누르면 데이터 탭으로 바꾼 뒤 해당 셀로 초점을 옮긴다.

### D23. 접근성 보강

- **예시 불러오기를 "선택 상자 + 불러오기 버튼"으로 바꿨다.** 이전에는 고르는 즉시 불러오고 선택을 비워서, 키보드 방향키로는 첫 예시 다음 항목에 닿을 수 없었다(키보드만으로 하는 E2E에서 발견).
- 본문 바로가기 링크, 차트 흐름 목록 표(스크린리더 전용), 대화상자를 닫으면 연 버튼으로 초점 복귀.
- axe 검사(serious·critical 0건)를 첫 화면·오류 상태·순환 상태·가져오기 창·열 맞추기·내려받기 창·모바일 세 탭에서 실행한다.
- 수용 기준 A7을 E2E로 확인: 마우스 없이 예시 선택 → 값 수정 → 내려받기 창 → 파일 이름 입력 → PNG 내려받기.

### D24. 보안·개인정보(T4.4)

- 배포 빌드에만 CSP 메타 태그를 넣는다(`connect-src 'self'` 등). 개발 서버는 인라인 스크립트(HMR)를 쓰므로 넣지 않는다. E2E가 빌드본으로 돌기 때문에 CSP가 켜진 상태에서 PNG 만들기(blob·data URI 글꼴)까지 콘솔 오류 없이 동작하는지 검사한다.
- `referrer: no-referrer`, 시험 운영 동안 `robots: noindex`(저장소 변수 `SANKEY_INDEX=1`로 해제).
- 스크린리더 전용 표가 좁은 화면에서 페이지 폭을 넓히던 문제(표는 1px 폭 지정을 무시함)를 감싸는 요소로 고쳤다.

### D25. 배포(T4.5)

GitHub Pages. main의 CI가 통과하면 `deploy.yml`이 빌드·배포하고, 배포된 주소에서 스모크 테스트(첫 화면·접근성·외부 요청 0건·글꼴·PNG)를 돌린다. 하위 경로 배포는 로컬에서 `dist/`를 `/sankey/` 아래에 두고 같은 스모크 테스트로 확인했다. 처음 한 번은 저장소 설정에서 Pages 소스를 "GitHub Actions"로 바꿔야 한다(docs/DEPLOYMENT.md).
