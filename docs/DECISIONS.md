# 결정 기록

개발 계획 §2.2 잠정값의 확정·변경과 구현 중 내린 결정을 날짜순으로 남긴다.

## 2026-11-02 · S1 시제품

### D1. 최대 입력 행 수: 500행 유지 (T1.6)

측정 환경: 클라우드 개발 컨테이너, Node 22, 헤드리스 Chromium. 일반 사무용 PC보다 느릴 수 있으므로 여유를 두고 판단했다.

**계산(검증 → 그래프 → 레이아웃), `npm run perf`**

| 행 | 노드 | 링크 | 중앙값(ms) | 최대(ms) |
|---:|---:|---:|---:|---:|
| 50 | 35 | 45 | 1.9 | 2.8 |
| 200 | 72 | 180 | 4.4 | 5.1 |
| 500 | 115 | 441 | 8.7 | 10.8 |
| 1000 | 160 | 472 | 8.8 | 9.3 |
| 2000 | 219 | 483 | 10.0 | 22.0 |

(1000행 이상은 무작위 연결이 겹쳐 합산되므로 링크 수가 늘지 않는다.)

**브라우저(표 + SVG 다시 그리기)**

| 행 | 붙여넣기 → 표 표시 | 키 입력 → 화면 반영 | 입력 → 차트 갱신(디바운스 150ms 포함) |
|---:|---:|---:|---:|
| 200 | 92ms | 15ms | 202ms |
| 500 | 194ms | 21ms | 206ms |

**결정**: 500행 하드 제한과 200행 초과 안내를 그대로 둔다. 500행에서도 입력 지연이 체감되지 않는다(키 입력 반응 약 20ms). 제한을 올릴지는 S5 사용자 검토에서 실제 데이터 규모를 보고 다시 판단한다. 큰 표에서 레이블이 겹치는 가독성 문제가 성능보다 먼저 한계가 될 가능성이 높다.

### D2. 완전히 빈 행은 검증하지 않는다

새 행을 추가한 직후 "필수 항목 누락" 오류가 쏟아지지 않도록, 모든 셀이 빈 행은 입력 중인 자리로 보고 건너뛴다. 셀 하나라도 채우면 검증한다.

### D3. 오류 행만 빼고 나머지는 그린다

행 단위 오류(필수 누락·숫자 오류)가 있어도 다이어그램 전체를 막지 않고 그 행만 제외한다. 그리기 자체를 막는 경우는 순환 연결과 유효 행 0개뿐이다.

### D4. 노드 색상 그룹 배정 규칙

행의 "색상 그룹"을 노드에 붙일 때, 그 노드로 **들어오는** 첫 행의 그룹을 쓰고, 들어오는 행이 없는 시작 노드는 **나가는** 첫 행의 그룹을 쓴다. (예: `석탄 → 발전 [에너지원]`이면 석탄·발전 모두 에너지원, `발전 → 가정 [소비]`이면 가정은 소비.) S2 색상 설정에서 사용자 검토 후 바꿀 수 있다.

### D5. 실행 취소 단위

같은 셀을 1.5초 안에 연달아 입력하면 한 번의 실행 취소로 묶는다. 행 추가·삭제·붙여넣기·예시 불러오기는 각각 한 단계다. 예시 불러오기도 실행 취소로 되돌릴 수 있으므로 확인 대화상자는 두지 않았다. 기록은 최대 100단계.

### D6. 표 키보드 조작

Enter/Shift+Enter·↑/↓로 같은 열의 아래/위 행으로 이동하고, 마지막 행에서 Enter를 누르면 새 행을 만든다. Ctrl(⌘)+Enter는 현재 행 아래에 새 행, Ctrl(⌘)+Delete는 현재 행 삭제. 입력란의 기본 실행 취소 대신 문서 기록(Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y)을 쓴다.

### 알려진 문제(다음 단계에서 처리)

- **노드 색이 편집 중 바뀐다**: 색을 현재 그려진 노드 순서로 배정하므로, 앞쪽 행이 오류로 빠지면 뒤 노드들의 색이 밀린다. T2.2에서 입력 순서 기준의 안정적인 배정으로 바꾼다.
- **좁은 화면에서 레이블이 작다**: 차트를 화면 폭에 맞춰 줄이므로 모바일에서 글자가 작아진다. T2.3 확대·축소와 T4.2 모바일 탭에서 다룬다.
